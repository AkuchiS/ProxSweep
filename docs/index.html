ProxSweep

One command updates your whole Proxmox homelab — the host, every LXC, VMs and Docker — then checks everything came back.

v1.1.1 · MIT · single Bash script
Quick start View on GitHub Sponsor

What it does

Stop SSH-ing into each container. ProxSweep runs on the Proxmox host and sweeps the whole stack in one pass.

Host

Debian updates applied; Proxmox and kernel packages listed for you to install with a planned reboot.

LXC containers

apt, apk, dnf and opkg detected automatically — including the OS of containers that run Docker.

VMs

Updated through the QEMU guest agent. No SSH keys to manage.

Docker

Compose stacks via pull + up -d, so containers behind a VPN container are recreated together. Watchtower for the rest.

Safe by default

Built after real-world breakages: half-finished upgrades, containers that never came back, and failures logged as “OK”.

Snapshot first

Each guest is snapshotted before it changes. The log prints the exact rollback command.

Restarts that stick

Containers running old code are restarted and checked. Docker containers that stopped are started again.

Persistence checks

Flags guests without Start at boot and containers without a restart policy — and can fix them.

Guards

Skips guests that are low on disk, waits for busy package locks, and reports a stuck one.

Service checks

After the run, your web apps must answer — or it's an error.

Inventory

Reports new, removed, renamed and stopped guests since the last run.

Quick start

On the Proxmox host, as root.

  1. Install 
    curl -fsSL -o /usr/local/bin/pve_stack_updater.sh \
  https://raw.githubusercontent.com/AkuchiS/ProxSweep/main/pve_stack_updater.sh
chmod +x /usr/local/bin/pve_stack_updater.sh
  2. Check and preview — nothing is changed. 
    pve_stack_updater.sh --check
pve_stack_updater.sh --dry-run
  3. Schedule it nightly 
    echo '0 3 * * * root /usr/local/bin/pve_stack_updater.sh >> /var/log/pve_stack_updater/cron.log 2>&1' \
  > /etc/cron.d/proxsweep

Settings live in /etc/proxsweep.conf and survive updates. Full options are in the README.

Real output from a 20-container media server. Errors make the script exit with code 1, so cron mail or monitoring catches them.
